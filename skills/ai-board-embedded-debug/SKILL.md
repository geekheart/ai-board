# AI Board 嵌入式真板调试

## 目标

用户一次接好目标板和外设，提供器件型号、接线和业务要求。用目标板自己的构建、烧录和日志工具迭代固件。用 AI Board 切换接线、生成已知输入、观察真实信号和复验。交付目标代码、实测证据和可重跑的测试。

优先解决仍需人工改线、按键或代测的环节。逻辑分析、Lua 和网页工作台用于辅助实验、复用操作及回看结果。

## 选择执行方式

- **本机可访问目标板 USB 和 AI Board 局域网时**，用目标项目的工具链烧录或读日志，通过 Wi‑Fi 调用 `board_rpc.py` 操作工具板。在仓库内用 `tools/board_rpc.py`。从 ZIP 导入时用技能包内的 `scripts/board_rpc.py`，按实际固件核对参数。
- **在 ChatGPT 中运行时**，用当前会话中已连接、获授权且能访问设备的本机执行工具或 MCP。先读取实际暴露的操作和权限。局域网和 USB 可达性来自执行工具。只有代码、接线表或采集文件可用时，可以交付驱动、分析结果或可在本机执行的命令，把硬件结果标为待实测。
- 用实际板卡地址和本机私密密钥文件。读取板卡状态可以先用无副作用的 `status` 和 `control status`。需要连续写入时用接管租约，并在任务结束时释放。连接、配网和租约细节见 [CLI 与设备维护](references/board-cli-and-maintenance.md)。

## 执行真板闭环

1. 从用户说明、原理图或项目确认目标型号、目标固件仓库、USB 烧录和日志接口、BBX 接线、电平、共地、信号方向和可观察的验收条件。先读回工具板的实际路由、模式和租约。只补问会影响下一步操作的缺项。
2. 用可重复的参考实验确认外设或测量链路。例如调试 I²C 温度传感器时，让 C3 先独立访问传感器。或用官方 C 示例建立同一组引脚、供电和时钟条件下的参考读数。
3. 在目标项目编写功能并构建，经目标板自己的 USB、编程器或约定的更新通道烧录。保留可重刷的已知可用镜像。工具板自身的 Wi‑Fi OTA 用于更新 C3 的工具固件。
4. 用矩阵接通目标板和外设，按验收条件提供输入，读回目标日志、协议响应和必要的波形。先比较线上实际数据与目标固件看到的数据，再决定下一次改动。区分接线或外设故障、目标驱动错误和业务逻辑错误。
5. 失败时恢复可观测状态，再修复和重测。优先用目标板的 USB 复位或下载能力。确认适配的 EN 和 BOOT 接法后可预接供恢复使用。没有 EN 的目标可用 OUT 冷重启，先验证 USB 或其他电源不会维持供电。需要人工进入下载模式时，准确指出这一步。结束时汇报实测输入、结果与通过项，恢复临时路由或保留用户指定的测试现场。

只做某项采集、协议测试或维护时，直接走对应参考中的操作。
